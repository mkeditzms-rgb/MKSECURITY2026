02 / RELEASE HARDENING

Protect your Android app

Use multiple layers. No single website setting can stop every APK modification or reverse-engineering attempt.

01

Keep signing keys private

Never publish your keystore, passwords, private keys, or signing credentials in this repository. Back them up securely.

02

Verify release signatures

Sign the final APK with your own release key. Verify the signature and compare the signing certificate with your known release identity.

Android apksigner docs ↗
03

Obfuscate release builds

For apps built from source, use R8/code shrinking and obfuscation where appropriate. Obfuscation raises effort; it is not complete protection.

R8 documentation ↗
04

Check integrity in-app

Where appropriate, have the app or backend detect unexpected signing identities and suspicious changes. Client-side checks can be patched by a determined attacker.

05

Keep secrets server-side

Do not put API secrets, private tokens, or critical authorization rules inside an APK. Enforce sensitive permissions and decisions on a trusted server.

06

Publish trusted hashes

Share the official SHA-256 fingerprint through a trusted channel separate from the APK download. Users can compare it before installing.

Important: A SHA-256 hash changes if even one file byte changes, but a hash checker does not prevent edits. A modified APK can be resigned with a different key; users need a trusted signature or hash to identify the official release.

04 / KNOW THE LIMITS

Frequently asked questions

Does this website protect my APK automatically?

No. It provides a local SHA-256 checker and security guidance. It does not inject native .so libraries, obfuscate code, encrypt an APK, or add anti-tampering logic.

Can GitHub Pages run an APK protector?

No server-side processing runs on GitHub Pages. A static page can run JavaScript in a visitor's browser, but reliable APK rewriting, signing, and secure key management require a separate trusted build environment or service.

Is a SHA-256 match proof that an APK is safe?

No. A match means the file bytes match the reference hash you trust. It does not establish that the original file is benign or free of vulnerabilities.

Can I build this on an Android phone?

Yes. Use your phone browser to create a GitHub repository and edit index.html and assets/style.css. Desktop mode may make GitHub's editor easier to use.
